# 订单关联重复导致客单价偏高

当营业额、人均贡献和客单价偏高，而去重订单数与顾客人数正常时，先核查订单在维表关联后是否重复。常见情形是同一门店编号在不同POS记录中出现多次，订单只按门店编号连接后被复制；SUM(金额)扩大，COUNT(DISTINCT 订单号)不变。

用固定日期与门店编号对比关联前后行数、唯一订单数、金额合计和每单重复倍数，再看右表每个连接键有几行。不能仅凭两个群体的客单价恰好相同判错，也不能直接把金额统一除以2。

修复应落在放大行数的关联之前：核验同一门店编号的分公司、省份等归属一致后，将右表按门店编号和需要输出的归属字段去重，再保留原JOIN类型与输出绑定。只按名称去重可能混店；使用MAX强选冲突归属也会掩盖问题。如一个编号存在多个真实归属，应先明确有效日期或匹配规则，不能擅自丢行。

例如右表两条记录仅POS来源不同，均为`DEMO001 / 示例南区 / 示例省`，投影所需字段并去重后应只剩一条。JOIN后原订单号集合应完整保留，金额与未关联的事实源一致。

修复后顺序验证：源ETL成功完成、输出字段ID与绑定未变、固定窗口订单集合与金额对账、下游专供ETL完成、各输出水位更新，最后回读线上卡片和实际展示。历史同一窗口对账与刷新后的滚动窗口是两套证据，不混着比较。不要用ETL提交成功替代执行完成，或用脚本已发布替代页面已显示。

公开案例不包含生产订单、会员、真实编号、金额样本、资源ID或运行日志。
