## §1 一句话定位

**门店手机成绩单 = 原生 Page + 原生门店筛选器 + 一张 HTML SDK 父卡 + 19 个 DATA_GRID 视图。**

- 观远负责权限、刷新、聚合、换店联动。
- HTML 负责手机叙事：首屏数字、涨跌、走势、对比、下钻弹层。
- 标准图表卡只做数据供给，不做主视觉。
- 给老板看的是 **数字和波动**，不是归因、不是「今天做什么」、不是 RFM 营销策略。

这不是把桌面看板压进 390px。桌面页、单店固定页、手机成绩单是三条产品，不要互相覆盖。

## §2 产品形态（先锁死再写卡）

| 决策 | 为什么 |
|---|---|
| 手机优先，触控分段、下钻、滑块都在 HTML 里 | 加盟店老板主要在手机上看昨天 |
| 周期（昨天 / 近 7 天 / 近 30 天 / 本月）放在 HTML，不放原生日期筛选 | 原生日期一开，所有视图被同一时间宏切开，70 天财务窗口和「上月同期」推不出来；`guanvis` 对 TIME_MACRO / 多日期字段的映射也不稳 |
| 门店范围 **只** 由页面筛选器控制 | 卡片里再写死门店名，会和筛选器叠成 AND，换店后财务视图被滤空 |
| 对比块标题用「跟其他门店比」 | 「跟同行比」像行业对标，语义不对 |
| 对比只给 **名次 + 中位数** | 可以回答「我在这组里大概什么位置」 |
| **禁止**展示对比组有多少家有营业门店 | 看板一旦外流，家数能被用来估分公司 / 城市 / 全国规模 |
| 对比卡组名下面的空位写「近 7 天日均营业额」 | 说明口径，不拿家数填空 |
| 首屏默认看 **当天合计**；对比块看 **近 7 天日均** | 同一张财务表、两个口径。昨天 1.2 万、近 7 天日均 9 千，不是 bug |
| 不要 LLM 口吻的归因和建议 | 成绩单不是运营简报 |

交互清单（生产用页面筛选器换店；离线样本用页内两店切换代替）：

1. 周期：昨天 / 近 7 天 / 近 30 天 / 本月
2. 每日明细弹层
3. 堂食 / 外卖下钻到渠道
4. 走势：近 30 天折线 + 近 8 周柱 + 滑块看某天
5. 跟其他门店比：分公司 / 同城 / 门店类型（全国）三张卡 + 弹层
6. 渠道条
7. 顾客与会员：消费会员跟顶部周期走，按卡号窗口内去重，不是日均或每日加总；会员订单占比 / 新客占比 / 到店人次仍来自新老客表（人次是每日累加）
8. 会员和非会员：与顾客与会员、私域同级的一级模块，固定近 30 天，不跟顶部周期走。对照卡以人均贡献为主，客单价只做右侧备注，不要替换主数字，也不要另开客单价条；卡片上已有的人均到店 / 人均贡献不要再画重复条，只留组内营业额
9. 私域：存量（在联 / 在群）和本期新增（新加 / 核销）分开；流失率、退群率放存量健康度，不当漏斗
10. 哪些券用得最多：一级模块，跟顶部周期走，不要放在私域下面折叠
11. 饭点条（按单量倒序，名称带时段）紧挨热销菜；热销展开到前 15 + 汤底堂食/外卖切换
12. 口径说明

没有顾客标识聚合表、没有周期去重会员、没有 RFM，就宁缺毋滥，不要硬凑。页面不展示 RFM。次级数据条（中位、排行非第一条）用更深的杏色，不要用过淡的浅杏。

每一项在离线 HTML 里都必须仍有数。缺一块就不是完整样本。

## §3 架构与视图契约

```text
Page
├─ 原生门店筛选器（唯一门店范围）
│    linkTo(0..13, 15..18)  → 编译到卡片 ID
│    不要 link 第 14 个对比视图（对比要看全量有营业门店）
└─ HTML SDK 父卡
     ├─ 可见层：charts/*.html/css/js
     └─ 19 个 DATA_GRID children（GDPlugin data[]）
```

### 3.1 两套顺序不要混用

| 顺序 | 谁在用 | 能不能当 HTML 下标 |
|---|---|---|
| `views.push` / `addDataView` 写入顺序 | `selector.linkTo(n)` 编译成卡片 ID | **能**给筛选器，**不能**给 HTML |
| 观远 `children` / GDPlugin `data[]` | 运行时真正交给 `receive(data)` 的数组 | **不能**假设等于写入顺序 |

实测（2026-09-14，`guanvis 0.1.47`）：运行时常见顺序是

`fin, newold, soup, products, hours, status, friends, groups, frienddaily, groupdaily, coupons, membase, member, member7, member30, memberMonth, dormant, context, peer`

写入顺序则是财务 → 时段 → 新老客 → 会员 → 商品 → 汤底 → …。按 `data[2]` 当「新老客」会把汤底读成顾客，板块变空；CLI `card preview` 仍可能显示「卡里有数」。这是 **HTML 读错视图**，不是数据集没数。

**HTML 必须按列名识别视图**，签名如下（`detectV`）：

| 视图 | 识别列（同时/优先） | 用途 |
|---|---|---|
| fin | `同步时间` + `渠道名称` | 70 天财务，周期/走势/渠道全从这里推 |
| hours | `下单时段` | 近 7 天 vs 前 7 天饭点 |
| newold | `顾客属性` | 新客占比、人次 |
| member | `消费会员数` | 昨天（锚点当天）消费会员；跨日相加是人次，页面不这么加 |
| member7 | `消费会员_近7天` | 近 7 天窗口内卡号去重 |
| member30 | `消费会员_近30天` | 近 30 天窗口内卡号去重 |
| memberMonth | `消费会员_本月` | 本月 1 日到昨天卡号去重 |
| membase | `消费频次` + `营收贡献` | 近 30 天会员 vs 非会员；频次 = 去重订单 ÷ 去重人数 |
| products | `产品` | 近 7 天堂食热销 |
| soup | `口味` | 汤底，按堂食/外卖切 |
| status | `顾客状态` | 当前快照 |
| friends | `在联好友` | 私域存量 |
| groups | `在群人数` | 社群存量 |
| frienddaily | `添加日期` | 新加好友，随周期 |
| groupdaily | `入群日期` | 入群，随周期 |
| coupons | `核销券数` | 核销，随周期 |
| dormant | `复购状态` | 预留快照（页面可以先不渲染） |
| context | `开业日期` | 取门店名；没有则回退财务行的 `门店名称` |
| rfm | `顾客类型` | V1 不取。`detectV` 可留签名，运行时必须是 `-1` |
| peer | `营业天数` | 近 7 天日均对比 |

离线样本把 19 个视图按上面的运行时顺序打乱排放，就是为了逼 `detectV` 出场。不要改回「按下标写死」来图省事。

### 3.2 窗口怎么切

周期在 HTML 里算，锚点 = 财务视图里最新有数据的订单日（正常是昨天）。

| 窗口 | 建议 | 为什么 |
|---|---|---|
| 财务 / 新老客 / 消费会员 / 私域逐日 | 昨天往回 69 天（共 70 天） | 覆盖本月、上月同期、近 30 天 vs 前 30 天、近 8 周 |
| 用餐时段 | 昨天往回 15 天（共 16 天） | 近 7 天 vs 前 7 天，再留 2 天防「昨天还没同步」 |
| 热销 / 汤底 / 对比 | 昨天往回 6 天（共 7 天） | 备货和对比看最近一周就够 |
| 顾客状态 / 好友存量 / 在群 / 门店信息 | 快照，不跟周期切 | 文案要写清「当前」，避免老板以为随周期变。不取 RFM |

对比用「上周同一天 / 前一天 / 前 7 天 / 前 30 天 / 上月 1 日到同一天」。上月天数不够时，本月对比改日均。涨跌 0.5% 以内当持平。

日均只按 **有营业的天数** 除，停业日不当 0。

### 3.3 字段别名要和 HTML 一致

DATA_GRID 的度量别名必须写成 HTML 在读的中文名，例如财务 `income` → `营业额`，订单号 `COUNT_DISTINCT` → `订单数`。HTML 不认底层英文字段名。

商品视图要排除耗材（餐巾纸、打包盒等），汤底排除「未识别」。排除清单是业务配置，公开案例只保留通用耗材名，不要抄生产活动菜名。

## §4 发布链路（覆盖已有页）

```text
guanvis pack . -o ../official.zip
python3 compatibility_patch.py ../official.zip ../compatible.zip
guanvis upload ../compatible.zip --allow-overwrite
```

覆盖前备份，覆盖后分别看：手机页、`?pageRenderType=phoneView`、换店后财务是否还在。

### 4.1 为什么还要 phoneLayout 补丁

`guanvis 0.1.47` 的 pack **不写** `page.meta.phoneLayout`。手机编辑器会写；CLI 不写。不补的时候，手机视图按默认高度切 HTML 卡，成绩单被截成一截。

补丁只改 `page.meta`，业务数据、权限、其他资源不许动。升级 CLI 后先看 pack 是否已经带 `phoneLayout`，有了就停用脚本。

当前可用的手机布局（单筛选器 + 单 HTML 卡）：

```text
phoneLayout.layout
  group_StoreFilters   y=0  h=3
  HTML 父卡            y=3  h=38
layoutSetting.rowHeight = 14
toolbar = HIDDEN
卡片描边关掉（HTML 自己画纸面）
```

`h=38 × 14 ≈ 530px` 可视高度。再矮（例如 h=36 / 约 390px 预览）会把走势和对比挤出首屏。HTML 内部自己滚。

### 4.2 筛选器联动

`linkTo(n)` 的 `n` 是 **`views.push` 下标**，编译后变成卡片 ID。不要改成 GDPlugin 运行时下标。

对比视图（写入顺序里下标 15）**不要**挂门店筛选。挂了之后对比集只剩当前店，名次失去意义。周期消费会员（17–19）和近 30 天对照（16）必须挂门店筛选，否则换店后对照卡还停在默认店。

`linkToAll()` 联不到 custom chart 内部 dataView——这是 C-12 的老坑。本页用数字 `linkTo`，不要图省事改 `linkToAll`。

### 4.3 不要动的页面

- 桌面门店看板
- 单店固定页（店名写死在筛选或卡片上的那张）

手机成绩单是新页或指定手机页的覆盖发布。发之前把 page ID 写进回执，禁止「再 create 一张同名页」。

## §5 这条链路上踩过的坑

按出现顺序记。公开文档只留机制，不留真实店名和金额。

### 5.1 换店后财务空白（卡片级门店 AND 筛选器）

**现象**：默认店有数；筛选器换到另一家，首屏变成「近 70 天没有财务数据」。CLI 预览默认店仍正常。

**原因**：DATA_GRID 上写了 `门店名称 IN <默认店>`，页面筛选器又筛了另一家，AND 之后财务行数为 0。HTML 锚点算不出来，整页判空。

**修法**：

1. 卡片上删除全部门店过滤。门店范围只留页面筛选器。
2. 财务视图加一行 `门店名称`，给 HTML 在没有门店信息快照时回退店名。
3. `guanvis preview` 发布前扫一遍：自定义卡 payload 里不准再出现具体店名。

### 5.2 顾客 / 私域 / 时段 / 商品空白（按下标读错视图）

**现象**：财务首屏有数，下面几块是空的。iframe 里 `getData()` 能看到 20 列，但列名对不上你以为的下标。

**原因**：见 §3.1。`children` 顺序 ≠ `addDataView` 顺序。

**修法**：`detectV` 按列名。验收时打印 `views()` 映射，确认 `fin/newold/hours/products/...` 都不是 `-1`，再看板块数字。

**不要做的事**：看见 HTML 空了，就把 `linkTo` 改成 GDPlugin 下标。筛选器会绑错卡片。

### 5.3 对比块泄露出门店规模

**现象**：组名旁边或副标题写「N 家有营业门店」。

**为什么不行**：手机截图、转发、加盟商之间互看，家数就是规模情报。分公司 / 城市 / 「某类型（全国）」每一层都不能写。

**修法**：UI 只留组名、名次、分位、你 vs 中位。弹层可以有「前 25%」这种分位数字，仍然不写家数、不写其他店名。空位用口径说明填（「近 7 天日均营业额」）。

### 5.4 首屏和对比对不上（口径不同，不是取数 bug）

首屏「昨天」= 锚点当天 **合计**。对比 = 近 7 天营业额 ÷ 近 7 个营业日。同一张财务表。验收时先用同一店、同一天把两个口径都算一遍，再判断是不是坏了。

### 5.5 原生日期筛选把窗口切坏

财务需要 70 天才能推本月和近 8 周；时段需要 16 天才能做「近 7 vs 前 7」。页面级日期筛选会把所有视图切成同一段，HTML 周期按钮只是在已经被切短的数据上再切一次。

本形态 **不要** 原生日期筛选。单店固定页如果仍用原生日期，那是另一条产品，不要和成绩单混改。

### 5.6 phoneLayout 缺失导致手机截卡

pack 后的 zip 若没有 `phoneLayout`，手机页只露出成绩单上半截。补丁见 §4.1。验收必须打开手机入口或 `phoneView`，不能只看桌面编辑态。

### 5.7 把建议文案写进成绩单

「今天做什么」、RFM 策略、归因段落会把数字页变成咨询页。加盟店场景里，建议对错都难负责，也容易过期。页面只保留口径说明。

## §6 验收清单

发布或改离线样本之后，按这个表点。数字必须是算出来的，不能口算。

**管道**

- [ ] 19 个视图都能被列名识别；`detectV.rfm` 必须是 `-1`
- [ ] 换店后面包屑店名、财务、顾客、私域、商品一起变，不会只变店名
- [ ] 对比视图不受门店筛选，名次在换店后仍能算
- [ ] 卡片 payload 里没有写死的店名
- [ ] 手机页 / `phoneView` 能滚完整页，HTML 卡没有被默认高度截断

**产品**

- [ ] 昨天 / 近 7 天 / 近 30 天 / 本月都有营业额、订单、客单、堂食外卖拆分
- [ ] 每日明细、堂食/外卖渠道弹层有表
- [ ] 近 30 天折线、滑块、近 8 周柱都有数
- [ ] 对比三张卡有名次和中位；任何可见文案都没有「N 家」
- [ ] 饭点条、渠道条有数
- [ ] 顾客与会员：消费会员跟周期去重、新老客条、当前状态有数；页面不渲染 RFM
- [ ] 会员和非会员是一级模块：人均贡献为主、客单价在右侧；下方只有组内营业额条
- [ ] 私域 KPI 有数；哪些券用得最多是一级模块，不在私域下折叠
- [ ] 热销能展开到前 15，汤底堂食/外卖都能出条
- [ ] 口径说明能打开
- [ ] 页面没有归因句、没有「今天做什么」、没有营销策略

**口径**

- [ ] 首屏昨天合计 ≠ 对比近 7 天日均（除非 7 天每天碰巧一样）
- [ ] 本月对比在上月天数不够时走日均
- [ ] 「数据到哪天」跟财务最新日一致；离线样本若冻结在过去某天，顶部应写清这是冻结锚点，或把演示「今天」设成锚点次日，避免被当成同步故障

**脱敏（公开仓库 / 离线 HTML）**

- [ ] 无真实品牌、门店、人名、活动名
- [ ] 无真实 page / dataset / card / 筛选器 ID
- [ ] 无真实金额、会员量、好友量、对比组家数
- [ ] 私域文案用通用词（企微好友 / 社群 / 券），不用内部产品黑话
- [ ] 页顶有「脱敏演示 · 虚构数据」

## §7 离线样本怎么用

路径：`examples/store-mobile-scorecard/`

| 文件 | 作用 |
|---|---|
| `store-mobile-scorecard.html` | 交付物。双击用浏览器打开，全部交互离线可点 |
| `scorecard.js` / `scorecard.css` | 与生产成绩单同构的可见层（演示启动，不依赖 `GDPlugin`） |
| `build.mjs` | 生成两套虚构门店的 GDPlugin 列式数据，打乱视图顺序后内联进单文件 HTML |
| `README.md` | 打开方式与验收点击清单 |

```bash
node examples/store-mobile-scorecard/build.mjs
```

生成器会自检：除 RFM 外都能被列名识别；昨天合计和近 7 天日均不是同一个数；会员频次高于非会员且两店不同；对比组 ≥ 3 家（只用于算名次，页面不展示家数）。

生产发布 **不要** 拿这个 HTML 当 guanvis 工程去 upload。它没有 DATA_GRID、没有筛选器、没有权限。要上线，仍走 §4：原生 Page + 父卡 + 19 视图 + phoneLayout。
