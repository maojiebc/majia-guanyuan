# 受限环境取数：v3.4.0 验证记录

2026-10-12 验证记录。原始定义、环境名、资源标识、账户信息和取数输出在仓库外私有目录；本仓库只有合成示例与通用工具。没有向正式生产 BI 发请求。

## 实际验证

用户先指定独立测试环境，再单独授权尝试新建专用沙箱。官方 create 申请了 ID 并初始化本地工作区；首次保存前服务端尚未持久化，已有 edit 无法用这个 ID 回读。改为在私有允许名单中保存种子工作区，逐次复制状态并重新生成输入/SQL-only 图。实际 export 和 preview 成功，全程未 save、run、schedule，也未新建物化数据集。

一个小型数据集执行 COUNT 汇总，官方终端表格严格解析成一行结果。相同控制范围的 SQL 计数与 ds preview 的 rowCount 一致；预览前后来源版本/更新时间一致，临时目录已清理。产生 result.json、provenance.json 和报告备注的出处底稿。控制核对证明该小范围的完整输入汇总，不是任意大表或业务 SQL 的全量正确性证明。

另在一个超过终端预览样本规模的测试数据集复核，COUNT 汇总同样等于接口的可见总数，证明这两次汇总没有把首批样本当完整输入。未扩大到生产大表。

一个有 DATE 字段的数据集，以明确单日和单记录筛选执行分块读取，返回数与筛选后的 rowCount 一致且远低于上限。JSONL 哈希/行数读回通过；完成后 resume 跳过该块，没有重发取数。该测试没有覆盖历史全集、多用户争抢或真实超时恢复。

发现 raw 模式仍返回全部列；--columns 只是 CLI 显示投影，脚本现按真实字段位置在本地投影后落盘，不以此声称减少服务端读取量。

不可相加标记依据本地已有真实定义的 TABLE_CALC → advValue.baseTableCalc.category=RUNNING_TOTAL，以及 COMPARATIVE/valueType=RATE、LEVEL_PERCENTAGE 等结构；原生 RUNNING_TOTAL 对照已安装官方文档。快照只作定义证据，没有调用生产预览。未知高级计算和普通 SUM/COUNT 都不猜成可相加。

## 离线覆盖

合成回归涵盖：命令/选项白名单、目标 profile、超时进程组清理、截断与解析拒绝、校准不一致、工作区清理、私有输出路径、触顶拆分、数量不一致丢弃、单日阻碍、完成块不重发、来源版本、慢请求暂停、未知请求跨目录持有、人工终态声明后只处理缩小的范围、文件哈希损坏、空结果、重复候选键和不可相加定义。两个新示例只用 FakeCLI，不访问真实 BI。

## 限制

ETL preview 没有已验证的 JSON 结果接口；终端输出的单元格保持字符串，不能保证原始数值类型或未被展示精度处理。只接受简单 ASCII 列别名与单元格、最多 20 行/10 列的小结果。模糊、精简或不支持的格式直接失败。

单机锁不能发现网页和其他工具的任务。任何客户端超时都不能当作服务端结束；resolve-unknown 只记录人工审阅的独立终态声明，不负责获取或证明该终态。真实远端超时、慢请求和最大上限拆分未主动制造，仅用合成回归核对状态转换。

官方已审阅版本表与聚合包基线保持不变。此文档记录功能验证；各渠道的发布状态以对应版本回读为准。
