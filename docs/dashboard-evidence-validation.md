# 看板口径验收：v3.3.0 验证记录

验证日期：2026-09-30，Asia/Singapore。官方查询基线：guancli 1.0.63。原始证据保存在私有本地目录，公开仓库只包含方法、合成样例与脱敏结论。

本次参考 [JeremyWXL/guanbi-agent-builder](https://github.com/JeremyWXL/guanbi-agent-builder) v4.8.1 的档案与验收工作流。真实后台对照显示，需要修正默认筛选继承、展示数值处理、行/字段绑定及定义变化检测。本版本重新实现这些部分，来源与 MIT 原文见 [致谢](../ATTRIBUTIONS.md)。

## 真实只读验证

在一个真实 BI 租户，以现有已登录 profile 对照一张会员日报和一张门店手机看板。提取 34 张卡片的定义，只选 9 张已有普通图表/数据视图取数；没有新建或修改正式资源。

会员日报：4 个 KPI、统计日期及分公司汇总共 6 项断言，与先前独立官方取数吻合。原始数值保留了精度，不受“人”“家”、千分位或百分号的展示影响；去重聚合及时间宏作为定义保留。

手机看板：官方 CLI 解析“分公司 → 门店”的默认级联后，财务、门店档案和周期会员均限定在同一所选门店。固定日期的四个渠道，各对账营业额和订单数；另核对门店身份与周期会员，共 10 项断言通过。参照数值来自之前独立读取的原始结果，验收 expected 没有从本次结果回填。

总计 16 项正向断言全部通过。5 项负向控制全部拒绝：另一渠道的金额冒充 POS、错误门店、错误日期、错误数值字段、错误取数范围指纹。这是结构化数据断言的验收结果，不是大模型自然语言问答准确率。

另外单独验证 CUSTOM 前端卡片被标记为不支持自动数据验收，没有向它请求 preview；将真实财务卡行数上限设为 2 后，结果标记为可能截断并拒绝通过。所选数据卡完成取数不代表 CUSTOM 中的二次计算、交互和渲染已验收。

## 适用边界

这次验证覆盖选定页面定义、默认筛选取数和明确的数据断言，没有验证所有页面、所有日期、上游 ETL SQL、指标平台、SQL 直查、前端渲染或任意自然语言问题。定义档案保持 draft；业务含义和可跨期间汇总的规则需要另行确认。

工具没有生产写入路径。这轮审计记录 26 次官方只读调用（16 次 page get、10 次 card preview），生产写入为 0；CUSTOM 控制没有调用 preview。验证开始和结束分别回读两张页面，其定义指纹与更新时间均一致。
