# 迭代节奏与实战门槛

2026-10-13 用户授权制定策略并立即开始第一轮能力迭代。

每周检查观远官方聚合包、六组件、随包 Skill 与附属项目的新提交。有与本 Skill 有关的实际兼容改动才发 patch；没有变化或只有不相关能力时不凑版本。检查失败不是无更新，基线只在审阅完毕后推进。已有作者反馈先回读，不能每周重复评论或提 PR。

每三周选择一个近期真实任务里反复出现的缺口，做一个可独立交付的能力版本。兼容新增用 minor，破坏已有接口才用 major；“大版本迭代”表示完成一轮能力闭环，不是每次强行抬首位版本。每轮必须有明确范围、负载预算、真实小范围实操和错误控制；生产资源遵守当前授权，真实材料保持私有，公开示例只用合成数据。离线测试不能代替真实验证，也不能继承上游的测试结论。

首轮 v3.5.0 选择分块取数后的独立验收与数字出处，见 [实操记录](extraction-evidence-validation.md)。后续候选是受限环境取数前体检、同口径对账定位和未知请求恢复证据；实际选择取决于最近任务，不预先承诺全部实现。

同一轮未完成时续做，不另开版本。完成兼容审阅、回归、实操与隐私检查后按 majia-ota 发布到已授权渠道，从提交导出、回读准确版本、同步本机并保留软链。上传超时或审核待处理只核验，不盲重发。网站、npm、社交及生产写入分别按对应授权处理。周期由本机已保存定时任务控制，配置成功不等于已自然运行；无变化或不可行动的等待状态保持安静。
